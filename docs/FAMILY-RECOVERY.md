# Возврат семьи — 0.19.0 alpha

## Использование

Альбом → «Возврат» → свой персонаж → «Вернуть ко мне». Нужно стоять на земле, держать альбом и иметь безопасную поверхность рядом. Запреты: полет/сон/вода/лава/наблюдатель, поводок и пассажир/транспорт персонажа. Команда разрешает вернуть ожидающего персонажа, но не переключает его в следование. Его дом остается в исходном измерении; перенос не перепривязывает маркер.

Сервер проверяет владельца, сессию альбома, возрастание номера команды и наличие записи в приватном снимке. Реестр хранит UUID, владельца, вид, имя (80 символов), последнее измерение и блок. Обновление при присоединении, каждые 100 тиков и перед выгрузкой/сменой измерения. Данные — `data/dudunka_family_registry.dat` в обычном SavedData Overworld.

Поиск: до 100 серверных тиков, transient TicketType с expiry 200 тиков, distance 0 (FULL) только исходного чанка. Не persistent Forge chunk forcing. Максимум 8 поисков на сервер, один на владельца, 200 тиков между попытками. Обычные тики не сканируют другие чанки. При успехе/ошибке/отмене/остановке сервера билет снимается; UUID разыскивается среди загруженных уровней, затем в загруженном последнем чанке. Перемещение — штатный Entity.teleportTo(ServerLevel,...), не создание из резервного NBT. Предварительный экземпляр используется только для проверки размеров/коллизий и не добавляется в мир. Проверяются пол, жидкости, огонь/опасные блоки/порталы, граница, загруженность и занятость живыми сущностями.

Потеря альбома из рук, смена измерения игрока, удаление игрока или замена сессии отменяют выполнение при следующем серверном тике. Обычное закрытие GUI не посылает отдельный пакет отмены: уже отправленная команда может закончиться, клиентский ответ не открывает закрытый экран. Снимок ограничен 32 записями; для нового снимка переоткрой альбом. Запись последнего места не гарантирует существование сущности: устаревший индекс заканчивается отказом без воскрешения. Время при лаге считается в серверных тиках.

## Переноска

`dudunka_carriers.dat` теперь сохраняет полный NBT Сюси вместе с UUID/владельцем/билетом/статусом. Backup копируется, не возвращается как изменяемая ссылка. Новая переноска получает backup при capture. Старый действительный предмет может передать backup при проверенном выпуске; после повторного capture он защищен полностью.

«Восстановить переноску» требует своего carried-билета и backup. Уже имеющийся в инвентаре действующий предмет запрещает повторную выдачу; ищутся основной инвентарь, броня и вторая рука. Для результата нужен свободный основной слот либо одиночная пустая переноска. Сначала проверяется возможность выдачи, затем на серверном потоке меняется билет и ставится предмет. Полный инвентарь/чужой владелец/отсутствующий backup не изменяют билет. Старая переноска в сундуке/на земле может физически сохраниться, но после ротации не выпускает сущность. В глобальном реестре только один действующий билет. При выпуске используется серверный backup; измененный NBT предмета не меняет доверие/возраст.

## Границы

Существующий мир поддерживается, но требуется хотя бы одна загрузка старого персонажа для индексации. Поиск не читает все региональные файлы. Потерянные до обновления предметы без backup невосстановимы. Удаленное измерение, удаленная сущность, поврежденные/несогласованно восстановленные playerdata/entity/SavedData файлы не исправляются. Разные Minecraft-файлы не являются одной атомарной транзакцией; это защита штатных операций и копий предмета, не обещание crash-atomic сохранений.

Не меняются модели/текстуры, самостоятельное догоняние 0.15, привязки домов, рост, забота или правила дружбы. Полный BMC4, моды территорий и реальный клиент требуют игровой приемки.


## Ответы альбома — 0.20.0

Результат содержит серверный код причины и оставшуюся паузу в пределах 0–10 секунд. Различаются неподходящее положение хозяина, небезопасное/тесное место, поводок/транспорт, отсутствующее измерение, таймаут поиска, уже выполняющийся поиск, отсутствие backup, имеющийся действующий предмет и полный инвентарь. Неавторизованные запросы не раскрывают частные данные. Неудачный поиск сообщает только «не найден в последнем известном месте», а не смерть/удаление. Успех переноса и восстановления переноски имеют отдельные ответы.

Пауза поиска отображается обратным отсчетом на клиенте; сервер остается источником разрешения, при лаге клиентская оценка может закончиться раньше. Все ограничения, лимиты поиска, снятие transient tickets и ротация билетов 0.19 сохранены. Протокол альбома 5 требует одновременного обновления сервера и клиентов.
